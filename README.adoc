A VPN killswitch daemon for qBittorrent — monitors your public IP on a configurable interval and automatically pauses all torrents the moment your VPN drops, then resumes them once the VPN is restored.

image:https://img.shields.io/badge/license-MIT-blue.svg[MIT License]
image:https://img.shields.io/badge/built_with-Rust-orange.svg[Built with Rust]
image:https://github.com/Londopy/qbit-killswitch/actions/workflows/ci.yml/badge.svg[CI,link=https://github.com/Londopy/qbit-killswitch/actions/workflows/ci.yml]

== What is this?

When you download torrents through a VPN, your real IP address is exposed to every peer in the swarm the moment the VPN disconnects — even briefly. Most torrent clients have no built-in protection against this.

qbit-killswitch sits in the background and watches your machine's public IP address. The first IP it sees after launch is recorded as your "safe" VPN IP. Every few seconds (configurable) it checks again. If the IP ever changes — or stops being reachable — it immediately tells qBittorrent to pause every active torrent. Once the VPN comes back and the same IP is seen again, it resumes them automatically.

It runs as a small system-tray app on Windows, Linux, and macOS. No command-line required after the first setup.

== Features

* *Automatic kill switch* — pauses all torrents immediately when the detected IP stops matching your VPN IP
* *Auto-resume* — resumes torrents as soon as the VPN IP is detected again
* *Configurable fail threshold* — tolerates transient IP-check failures before triggering a pause
* *Multiple IP-check services* — round-robins through a fallback list so a single dead service never causes a false positive
* *Re-pause enforcement* — torrents manually resumed outside the daemon are detected and re-paused during killswitch mode
* *OS keychain integration* — password stored in Windows Credential Manager / macOS Keychain / Linux Secret Service instead of plaintext
* *System tray icon* — colour-coded status dot (green / yellow / red / cyan) with a right-click context menu
* *Launch at startup* — optional autostart via registry (Windows), XDG autostart (Linux), or LaunchAgent (macOS)
* *Minimize to tray* — closing the window hides it rather than quitting
* *Re-detect VPN IP* — one-click button and tray menu item to re-anchor the daemon to a new VPN exit IP

== State machine

[source]
----
STARTING ──► NOMINAL ◄──► DEGRADED ──► PAUSED
                 ▲                        │
                 │                        │
             RECOVERY ◄───────────────────┘
----

[cols="1,1,3",options="header"]
|===
|State |Colour |Meaning

|STARTING
|Grey
|Waiting for the first successful IP fetch to anchor the VPN IP.

|NOMINAL
|Green
|Current IP matches the recorded VPN IP.

|DEGRADED
|Yellow
|IP mismatch or fetch failure detected; counting toward the fail threshold.

|PAUSED
|Red
|Threshold reached — all torrents paused. Re-pause enforcement active.

|RECOVERY
|Cyan (blinking)
|VPN restored; attempting to resume torrents.
|===

== Installation

=== Build from source

[source,bash]
----
git clone https://github.com/Londopy/qbit-killswitch.git
cd qbit-killswitch
cargo build --release
----

The binary is placed at `target/release/qbit-killswitch` (or `qbit-killswitch.exe` on Windows).

=== First run

[source,bash]
----
./target/release/qbit-killswitch
----

On the first launch the settings panel opens. Fill in your qBittorrent URL, username, and password, then click *Save*. The daemon begins monitoring immediately.

== Configuration

The config file is created automatically on first save:

[cols="1,3",options="header"]
|===
|Platform |Path

|Windows
|`%APPDATA%\qbit-killswitch\config.toml`

|Linux
|`~/.config/qbit-killswitch/config.toml`

|macOS
|`~/Library/Application Support/qbit-killswitch/config.toml`
|===

=== config.toml reference

[source,toml]
----
# qBittorrent Web UI
qbit_url  = "http://127.0.0.1:8080"
qbit_user = "admin"
qbit_pass = ""           # blank when use_keychain = true

# Keychain
use_keychain = true      # store password in OS credential store

# IP check
ip_check_urls = [
    "https://api.ipify.org",
    "https://ifconfig.me/ip",
    "https://icanhazip.com",
    "https://checkip.amazonaws.com",
]

# Monitor behaviour
poll_secs      = 30      # seconds between IP checks (min 5)
fail_threshold = 3       # consecutive failures before pausing

# Application
launch_at_startup = false
minimize_to_tray  = true
----

NOTE: When `use_keychain = true` the password is never written to disk. `qbit_pass` in the TOML will always be blank.

== Usage

=== GUI

The main window shows:

* A colour-coded status dot and label (state + VPN IP)
* A *Re-detect VPN IP* button — use this after switching VPN servers to anchor the daemon to your new exit IP
* Settings fields for all config options
* *Test Connection* — validates credentials against qBittorrent before saving
* *Save* / *Cancel* — unsaved changes are flagged; closing with pending edits shows a confirmation dialog

=== Tray menu

Right-click the tray icon to access:

* *Open qbit-killswitch* — show the main window
* *Status / VPN IP* — read-only informational items
* *Resume all torrents* — manual resume (available when paused/degraded)
* *Pause all torrents* — manual pause
* *Re-detect VPN IP* — re-anchor to current IP
* *Quit* — exit the daemon (torrents will not be automatically managed after this)

== How it works

1. On startup the daemon enters *STARTING* state and polls until it gets a clean IP response. That IP becomes the reference VPN IP.
2. On every poll tick the current public IP is fetched (trying each URL in `ip_check_urls` in order until one succeeds).
3. If the IP matches the reference → *NOMINAL*.
4. If it does not match, or all services are unreachable → increment fail streak → *DEGRADED*.
5. When the fail streak reaches `fail_threshold` → pause all torrents → *PAUSED*.
6. While paused, any torrents resumed outside the daemon are detected and re-paused automatically.
7. When the reference IP is seen again → *RECOVERY* → resume all torrents → *NOMINAL*.

The daemon also re-authenticates with qBittorrent automatically if the session cookie expires (HTTP 403).
